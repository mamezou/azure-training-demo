# リソースグループの管理

## 概要

このデモでは、Azureリソースグループの作成、管理、削除方法を学びます。
リソースグループはAzureリソース管理の基本単位であり、関連するリソースをまとめて管理できます。

## 学習目標

- リソースグループの概念を理解する
- リソースグループの作成方法
- タグを使用したリソースの整理
- リソースグループの削除方法
- リソースグループのベストプラクティス

## 前提条件

- Azureアカウント
- Azureサブスクリプションへの共同作成者以上の権限

## 所要時間

約15分

## 手順

### ステップ 1: リソースグループの作成

1. Azureポータル (https://portal.azure.com) にログイン
2. 検索バーで「リソース グループ」を検索
3. 「リソース グループ」サービスを選択
4. 上部の「+ 作成」ボタンをクリック

### ステップ 2: リソースグループの基本設定

「基本」タブで以下を設定：

1. **サブスクリプション**: 使用するサブスクリプションを選択
2. **リソース グループ**: `rg-az900-demo-01` と入力
3. **リージョン**: `Japan East` を選択

**ポイント**:
- リソースグループ名は、サブスクリプション内で一意である必要があります
- リージョンは、リソースグループのメタデータが保存される場所です
- リソースグループ内のリソースは、異なるリージョンに配置できます

### ステップ 3: タグの追加

1. 「タグ」タブをクリック
2. 以下のタグを追加：

| 名前 | 値 |
|------|------|
| Environment | Demo |
| Training | AZ-900 |
| Owner | [あなたの名前] |
| CostCenter | Training |

**ポイント**: タグは、リソースの整理、コスト追跡、ポリシー適用に役立ちます。

### ステップ 4: 確認と作成

1. 「確認および作成」タブをクリック
2. 設定内容を確認
3. 「作成」ボタンをクリック
4. 作成が完了するまで待機（通常は数秒）

### ステップ 5: リソースグループの詳細を確認

1. 作成したリソースグループをクリック
2. 以下のブレードを確認：

#### 概要ブレード
- リソースグループの基本情報
- サブスクリプション、リソースグループID
- 含まれるリソースのリスト（現在は空）

#### デプロイ
- デプロイ履歴を確認
- リソースグループの作成がデプロイとして記録されている

#### アクティビティログ
- 「書き込みリソースグループ」操作が記録されている
- 誰が、いつ、何を実行したかを追跡できる

#### アクセス制御 (IAM)
- ロール割り当ての表示と管理
- 現在の権限を確認

#### タグ
- 設定したタグを確認
- タグの追加・編集・削除が可能

### ステップ 6: 追加のリソースグループを作成

練習のため、もう2つリソースグループを作成します：

1. **2つ目のリソースグループ**:
   - 名前: `rg-az900-demo-02`
   - リージョン: `Japan East`
   - タグ: Environment=Development, Training=AZ-900

2. **3つ目のリソースグループ**:
   - 名前: `rg-az900-demo-03`
   - リージョン: `Japan West`
   - タグ: Environment=Production, Training=AZ-900

### ステップ 7: リソースグループのフィルタリング

1. 「リソース グループ」の一覧ページに戻る
2. 上部の「フィルターの追加」をクリック
3. フィルター条件を選択：
   - **名前**: `demo` を含む
   - **タグ**: `Training:AZ-900`
4. フィルターが適用され、該当するリソースグループのみ表示される

### ステップ 8: リソースグループのエクスポート

1. いずれかのリソースグループを開く
2. 左側メニューから「設定」>「エクスポート テンプレート」をクリック
3. ARMテンプレート（JSON形式）が表示される
4. 「ダウンロード」をクリックしてテンプレートを保存（オプション）

**ポイント**: エクスポートしたテンプレートを使用して、同じ構成を再現できます。

### ステップ 9: Cloud Shellでリソースグループを管理

1. Cloud Shellを起動
2. 以下のコマンドを実行：

```bash
# リソースグループの一覧表示
az group list --output table

# 特定のリソースグループの詳細表示
az group show --name rg-az900-demo-01 --output json

# タグでフィルタリング
az group list --tag Training=AZ-900 --output table
```

### ステップ 10: リソースグループの削除

⚠️ **警告**: リソースグループを削除すると、その中のすべてのリソースも削除されます。

1. 「リソース グループ」の一覧ページに移動
2. 削除するリソースグループ（`rg-az900-demo-01`）をクリック
3. 上部の「リソース グループの削除」をクリック
4. 確認のため、リソースグループ名 `rg-az900-demo-01` を入力
5. 「削除」ボタンをクリック
6. 削除が完了するまで待機（通常は数秒〜数分）

**Cloud Shellでの削除**:

```bash
# リソースグループの削除（確認なし）
az group delete --name rg-az900-demo-01 --yes --no-wait

# 削除ステータスの確認
az group list --output table
```

## 確認事項

以下ができることを確認してください：

- ✅ リソースグループを作成できる
- ✅ タグを追加できる
- ✅ リソースグループの詳細を確認できる
- ✅ フィルタリングを使用してリソースグループを検索できる
- ✅ Cloud Shellでリソースグループを管理できる
- ✅ リソースグループを削除できる

## クリーンアップ

残りのリソースグループを削除：

```bash
az group delete --name rg-az900-demo-02 --yes --no-wait
az group delete --name rg-az900-demo-03 --yes --no-wait
```

または、ポータルから各リソースグループを削除してください。

## 補足説明

### リソースグループのベストプラクティス

1. **ライフサイクルの一致**: 同じライフサイクルを持つリソースをグループ化
   - 例: Webアプリ、データベース、ストレージを1つのリソースグループに

2. **環境ごとの分離**: 開発、テスト、本番を別々のリソースグループに
   - 例: `rg-myapp-dev`, `rg-myapp-test`, `rg-myapp-prod`

3. **命名規則の統一**: 組織全体で一貫した命名規則を使用
   - 例: `rg-[プロジェクト名]-[環境]-[リージョン]`

4. **タグの活用**: コスト管理と整理のためにタグを使用
   - 必須タグ: Environment, CostCenter, Owner, Project

5. **リージョンの選択**: 
   - リソースグループのリージョンは、含まれるリソースとは独立
   - 地理的に近いリージョンを選択してレイテンシーを最小化

### リソースグループのロック

重要なリソースを誤って削除しないように、ロックを設定できます：

1. リソースグループを開く
2. 「設定」>「ロック」をクリック
3. 「+ 追加」をクリック
4. ロックタイプを選択：
   - **CanNotDelete**: 削除を防止
   - **ReadOnly**: 変更を防止
5. ロック名と注意事項を入力

### リソースの移動

リソースは別のリソースグループに移動できます：

1. リソースグループを開く
2. 移動するリソースを選択
3. 「移動」>「別のリソースグループに移動」
4. 移動先のリソースグループを選択

**制限事項**: 一部のリソースタイプは移動できません。
